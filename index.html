设计原则

这四条同时约束提示词、代码校验和界面。任何一条做不到，就宁可不改，保留原文。

01不改意图

提问仍是提问，“看看”不升级成“修改”。增强只让表达更清楚，不替用户做决定。

02不编造

草稿和上下文里没有的信息，一律不写成事实；有歧义就写进“需要先确认”。

03原样保留

代码、路径、网址、数字、技能、附件、引用、粘贴卡片逐字不变，由代码兜底校验。

04用户掌控

先预览再采用，任何时候可取消；采用后一步撤销，失败时原文一个字都不动。

动效规格

时长和曲线沿用现有输入框：颜色过渡 140ms；位移与尺寸用 cubic-bezier(.2,0,0,1)；输入框按下沿用 180ms 的回弹曲线。所有动效都在 Window.reduce-motion 下退化。

元素触发属性时长曲线减少动态效果时
一次增强最多只有一处在动：生成中是文字扫光，预览时是逐行进入，采用后只剩一条 6 秒的细线。不叠加多处动画，也不用弹跳、缩放、彩色渐变。

Host 处理流程

      
    
        
  1. 校验输入。正文 1–8000 字；同一客户端同时只允许一个增强请求，新请求到来时取消旧请求。
    2. 
        
  2. 组装上下文。有 TaskId 时，从会话取最近 1–2 轮，压缩到 1500 字以内；粘贴文本只取前 1000 字；附件只取类型和文件名。
    3. 
        
  3. 防止标签逃逸。正文和上下文中出现的 <draft>、</draft>、<context> 等标签字面量先转义，再放进对应标签。
    4. 
        
  4. 调用网关。复用 GenerateConversationIntelligenceAsync：输出上限 1200 Token、超时 15 秒、共用现有的 2 个并发槽位，推理档位取最低。
    5. 
        
  5. 清洗输出。去掉“以下是优化后的提示词：”这类前缀；去掉包住全文的代码块；识别 <<NO_CHANGE>>。
    6. 
        
  6. 校验结果。长度不超过原文 3 倍且不超过 800 字（原文更长时不超过原文的 1.2 倍）；原样校验，缺失项放进 PossiblyMissing。
    7. 
        
  7. 返回。enhanced 或 unchanged；失败时按现有错误码返回。正文不在 Host 落盘，也不写入诊断日志。
    8.

落地前需确认

      

        
新对话首页没有会话待确认
现有网关挂在 AgentExecutionSession 上。首页增强需要 Host 级入口，用当前默认提供方创建一次无会话调用。

        
推理档位待确认
网关当前取 reasoning.Choices.FirstOrDefault()。需确认这是最低档；增强应显式用最低档，避免推理模型耗时 10 秒以上。

        
富文本模式下的撤销待确认
需在 WindowsComposerEditor 下验证 ApplyPreparedDraft 是否进入原生撤销栈；不进入时，由控制器自己保存原文实现撤销。

        
用量归类待确认
网关已按 standalone 预留执行预算。用量统计里建议单列“提示词增强”，免得用户误以为任务本身变贵了。

        
流式输出第二版
现有网关是非流式的。第一版整段返回后逐行淡入；第二版再接入流式，边生成边显示。

验收标准

      
    
        
  1. 正文为空或只有空白时，按钮不可用。
    2. 
        
  2. 任何失败（超时、断网、未配置模型、取消）后，正文与增强前逐字一致。
    3. 
        
  3. 技能、附件、引用、粘贴卡片在增强前后完全不变。
    4. 
        
  4. 预览中按 ↵ 只会采用，不会发送消息。
    5. 
        
  5. 采用后 Ctrl Z 一步回到原文。
    6. 
        
  6. 按 Esc 取消后，Host 端请求随即中止，界面 200ms 内回到可编辑状态。
    7. 
        
  7. 15 秒内没有结果就判失败；同一客户端不会同时存在两个增强请求。
    8. 
        
  8. 评估集：意图偏离 0 条、编造 0 条、原样保留自动校验 100%、有明显提升 ≥ 80%。
    9. 
        
  9. 开启减少动态效果后，没有任何位移动画和循环动画。
    10. 
        
  10. 正文不进入诊断日志，也不在 Host 落盘。
